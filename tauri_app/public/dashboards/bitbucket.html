Cómo crear el API token (reemplaza a los App Passwords, que Atlassian ha ido retirando):
1. Ve a id.atlassian.com → Security → API tokens.
2. Crea un token con scopes acotados a Bitbucket: read:pullrequest:bitbucket, read:pipeline:bitbucket, read:repository:bitbucket, read:account.
3. Pega el token arriba junto con el email de tu cuenta Atlassian (no tu usuario de Bitbucket). Todo se guarda solo en localStorage de este navegador — nunca se envía a ningún sitio salvo api.bitbucket.org.
Este archivo es 100% local: ábrelo con doble clic o file://, no necesita servidor.
Notificaciones: pulsa la 🔔 de una PR para vigilar su pipeline; al concederse el permiso verás una notificación de confirmación inmediata, y cuando su pipeline termine (success/failed/error/detenido) saltará otra. Las casillas "Avisarme cuando" de arriba controlan avisos globales (PR nueva, actualizada, revisión pedida, pipeline fallido) para todas las PRs, no solo las vigiladas. Deja la pestaña abierta (puede estar minimizada) para que siga comprobando en segundo plano.
Si el navegador pide permiso pero nunca ves ninguna notificación (consola con Notification onerror): es Windows rechazando el aviso, no la página. Causas típicas, de más a menos probable en un equipo de empresa: 1) estás en una sesión de Escritorio Remoto (RDP)/VDI — las notificaciones toast de Windows fallan casi siempre ahí; 2) política de empresa bloqueando notificaciones del navegador (compruébalo en chrome://policy, busca DefaultNotificationsSetting); 3) Configuración > Sistema > Notificaciones de Windows con Chrome/Edge desactivado.
Por eso, además del aviso nativo, esta página tiene una alarma de respaldo que funciona aunque Windows bloquee las notificaciones: pitido audible + parpadeo del título de la pestaña cuando termina un pipeline vigilado con la pestaña oculta. No depende de permisos del sistema operativo. Cuando la Notification API no está disponible o el permiso no se concede, los avisos globales quedan igualmente registrados en un diálogo dentro de la página.
